# IDNE Documentation Style Guide

**Version:** 1.0  
**Status:** Draft

## Normative language

- **MUST:** mandatory requirement.
- **MUST NOT:** prohibited behaviour.
- **SHOULD:** recommended unless a documented reason justifies deviation.
- **SHOULD NOT:** generally prohibited unless a documented reason justifies it.
- **MAY:** optional.
- **OPTIONAL:** supported but not required.
- **DEPRECATED:** retained temporarily but should not be used in new material.

## Writing rules

1. Each rule MUST be testable or clearly identified as guidance.
2. One term MUST have one meaning throughout the project.
3. Internal identifiers MUST use stable uppercase prefixes.
4. Player-facing text MUST NOT expose internal identifiers or raw variables.
5. Examples MUST be labelled as examples and MUST NOT silently introduce new rules.
6. Adventure-specific facts MUST NOT appear in the reusable Engine Specification.
